# 网页 GM 综合运营控制套件设计

## 建设范围

在现有网页 GM 后台中增加以下已经确认的功能：

- 实时在线玩家中心。
- 玩家完整档案。
- 游戏运行时健康监控。
- 完整货币管理。
- 契约管理。
- 只读背包与装备查看。
- 公会增强管理。
- 运营统计。

货币、契约和公会功能允许修改数据；本期背包与装备功能仅提供查看，不提供修改。适合现有页面的能力直接合并，只有信息结构明显独立的功能才创建新页面。所有新增页面必须保持现有“深夜控制台”主题，并在完成后统一检查主题、弹窗层级、子窗口遮挡和响应式布局。

## 总体架构

采用数据库与 Frida 结合的混合控制方案：

- 数据库负责账号、离线角色、点券余额、契约、公会、历史记录和运营统计。
- Frida 负责游戏进程内的实时状态。所有 `CUser`、`GameWorld` 和 `CInventory` 读取或修改都通过现有主线程调度器执行。
- Java 后端将数据库资料与 Frida 返回的精简数值快照组合起来。中文角色名和物品描述由 Java 根据数据库与 PVF 解析，Frida 桥接继续使用紧凑的 ASCII JSON 协议。
- 所有修改操作都必须使用事务、请求编号、修改前后校验和操作审计。
- 浏览器不能直接访问 Frida，也不会开放原始 SQL、DP2 命令或任意封包接口。

## 页面结构

### 新建独立页面

#### 实时在线

在“玩家管理”下增加“实时在线”页面，提供：

- 以 Frida 实际在线结果为准的玩家列表，不依赖可能过期的登录表标记。
- 支持按账号、UID、角色名和角色编号搜索。
- 显示等级、职业、当前金币、疲劳、位置编号、队伍状态、公会、交易状态和在线状态。
- 页面不整体刷新，只更新列表数据和数字。
- 点击任意玩家可以打开共用的玩家档案页中页。

#### 运营统计

新增独立“运营统计”页面。日期筛选、趋势图和跨模块报表不适合塞入现有操作页面，因此保持独立。页面提供：

- 注册、日活、在线时长、副本活动、货币变化、奖励和公会活跃统计。
- 日期范围和指标筛选。
- 汇总指标、趋势图、分类表格，以及数据源没有历史记录时的明确提示。
- 只读导出当前筛选结果为 CSV。

### 合并到现有页面

#### 账号管理与角色管理

账号列表、角色列表、实时在线、公会成员和邮件查询结果共用同一个玩家档案页中页。页中页包含以下标签：

- 基本资料。
- 货币。
- 契约。
- 背包与装备。
- 邮件与奖励摘要。
- 公会与活动。
- 安全信息与后台操作记录。

#### 服务器监控

保留现有主机 CPU、内存、存储和网络指标，并增加“游戏运行时”和“服务状态”区域，用于展示游戏进程、Frida 桥接、进程资源、监听端口和日志新鲜度。

#### 公会管理

扩展现有公会管理弹窗，不再创建第二套公会页面。增加“公会设置、成员、申请、技能、公告、贡献记录”等标签。

## 后端组件

### Frida 运行时桥接

在现有仅监听本机回环地址的协议上增加受限制的操作：

- `online_snapshot`：返回精简的实际在线角色快照。
- `inspect_player`：返回当前角色状态、金币、疲劳、位置、队伍、公会和交易标记。
- `currency_snapshot`：返回可以安全读取的运行时货币余额。
- `change_gold`：按正负差值修改金币，带请求编号、精确差值校验和背包刷新。
- `inventory_snapshot`：返回背包、装备、宠物和账号仓库的数值型槽位数据。
- `inspect_contracts`：返回当前实际生效的契约类型和越级装备数值。

现有 `add_gold` 保持兼容，并在内部复用新的金币差值处理。每个运行时操作都必须校验账号 ID、角色编号、玩家状态、输入范围和主线程执行。Frida 桥接继续只监听 `127.0.0.1`。

### 运行时健康服务

新增独立健康服务，读取以下信息：

- 游戏进程 PID、运行时间、实际内存、线程数和可执行状态。
- Frida 桥接探活结果和响应耗时。
- 游戏、后端、Web 和运行时所需端口的监听状态。
- Java、Web 代理和登录器网关进程状态。
- Frida、DP2、游戏和网页后台日志的最后更新时间与当前文件大小。

健康检查全部为只读操作。某一数据源不可用时仍返回其他可用指标，并明确标记降级状态。

### 玩家档案服务

以角色编号作为主要查询目标，并在后端校验所属账号。返回数据库资料以及可为空的运行时资料。离线玩家仍能查看完整数据库档案，只有运行时字段显示为不可用。

服务继续使用现有中文编码转换工具处理旧数据库字符，并通过 `PvfManager` 补充物品名称、类型和图标信息。

### 货币管理服务

明确支持以下货币类型：

- 角色金币。
- 点券 `cera`。
- 代币券 `cera_point`。
- 复活币 `coin`。
- 付费硬币 `pay_coin`。
- 活动币 `event_coin`。
- 时装币 `avatar_coin`。
- PVP 胜点。

处理规则：

- 在线角色金币通过 Frida 修改，并在操作审计提交前核对修改前后余额。
- 离线角色金币和背包内货币通过数据库事务与行锁修改。
- 点券和代币券使用带上下限保护的事务修改，保持无符号整数范围正确。
- 无法安全核对的运行时货币在角色在线时禁止修改，页面明确提示需要离线后操作。
- 所有修改都采用“增加或扣减指定数量”，不开放无限制的绝对值覆盖。
- 本期不支持批量修改货币。

### 契约管理服务

以 `taiwan_login.member_premium` 作为数据库契约来源，并在后端建立明确的受支持契约类型清单。功能包括：

- 查看当前契约和已过期契约。
- 在线角色同时查看 Frida 实际生效的契约类型。
- 发放、延长、缩短和撤销契约。
- 校验起止时间，并使用事务完成防重复写入的新增或更新。
- 在线角色修改契约后，如没有经过验证的运行时刷新方式，明确显示“待重新登录生效”。

本期不直接修改玩家内存中的契约数据。现有霸王契约运行时检查继续作为实际生效状态的验证来源。

### 背包与装备只读服务

只读取背包、装备、宠物和仓库数据，不修改任何内容：

- 按当前 86 版本已知的背包与装备记录结构解析为不可变槽位数据。
- 无法识别或损坏的记录显示为不可用槽位，不猜测内容。
- 在适用时关联 `user_items` 和 `creature_items` 的规范化记录。
- 根据 PVF 补充物品 ID、名称、分类、稀有度、等级、图标和装备信息。
- 在线玩家使用 Frida `inventory_snapshot` 交叉核对，但不把它作为修改入口。

本期不提供背包删除、移动、发放、锁定、强化、增幅、锻造和随机属性修改接口。

### 公会增强服务

在现有事务型公会服务基础上增加：

- 公会经验、公会点数、资金、公告和技能点的查看与修改。
- 入会申请列表、批准和拒绝。
- 成员贡献修改。
- 移除成员时同步更新 `guild_member`、`charac_info`、`guild_info`、`guild_search` 和申请状态。
- 公会公告管理。
- 公会技能查看，以及不直接编辑技能 Blob 的受限技能点调整。

会长不能被移除、降级或替换，其他成员也不能被设置为职级 `1`。

### 运营统计服务

只允许参数化的只读统计查询，数据来源包括：

- 账号和角色创建记录。
- `member_play_info` 在线时长与活跃数据。
- 登录记录和当前实时在线快照。
- 可用的副本与地图历史日志。
- 点券流水、奖励记录和 GM 操作审计。
- 公会成员和贡献活动。

日期范围最多 366 天，分页大小有固定上限，分组维度采用后端白名单。客户端不能传入原始 SQL、表名或字段名。

### 后台操作审计

新增 `dnf_service.gm_operation_audit`，保存紧凑的审计记录：

- 管理员身份和客户端 IP。
- 模块、操作、目标账号和目标角色。
- 请求编号。
- 修改前和修改后的 JSON。
- 成功或失败状态及说明。
- 操作时间。

修改操作的请求编号保持唯一。审计记录沿用此前确认的最多保留 7 天策略。所有新增修改接口必须校验最高管理员权限。

## 接口组织

接口按功能分组：

- `/api/v1/gm/runtime/*`：实时在线快照和运行时健康。
- `/api/v1/gm/players/{characNo}/*`：玩家档案、货币、契约和背包。
- 继续使用 `/api/v1/gm/guilds/*`：公会增强功能。
- `/api/v1/gm/analytics/*`：只读运营统计。

列表接口继续使用现有分页结构。修改接口返回请求编号、修改前状态、修改后状态、同步状态和审计记录编号。

## 权限与参数校验

- 所有查询都要求管理员已经登录。
- 货币、契约和公会修改要求最高管理员权限。
- 后端根据角色编号查询所属账号，客户端不能提交互相冲突的账号 ID。
- 各货币类型分别设置修改范围和溢出校验。
- 危险操作确认包含新生成的目标令牌，避免用户在旧页中页上误改另一个玩家。
- 新功能不复用现有通用 SQL 执行接口。

## 错误处理

- 查询时 Frida 超时，仍返回数据库资料，并标记运行时状态降级。
- Frida 修改请求超时后先核对实际结果，再返回成功或失败；请求编号用于避免重复执行。
- 涉及多表一致性的数据库操作全部使用事务和行锁。
- 背包解析错误按单个槽位隔离，不影响玩家档案的其他内容。
- 运营统计显示数据源可用状态和最近一次成功更新时间。

## 前端设计

- 继续使用现有深夜控制台配色、间距、字体、表格密度、卡片、页中页、弹窗和状态样式。
- 紧凑操作使用图标；模式使用分段控件；玩家档案使用标签；修改操作使用确认弹窗；不熟悉的图标提供悬浮提示。
- 玩家档案页中页需要足够宽以展示表格，同时适配小屏幕。
- 表格使用稳定列宽，必要时允许横向滚动，不能把角色名、账号和编号压缩到无法识别。
- 图表沿用现有多色强调色，不新增单一颜色主导的主题。
- 统一检查弹窗、页中页、下拉列表、物品提示、普通提示和选择器弹层的层级关系。

## 测试要求

### 自动化测试

- Java 单元测试覆盖玩家档案聚合、货币边界、契约时间、审计幂等、背包解析、公会事务、统计筛选和健康检查降级结果。
- Node 测试覆盖每个新增 Frida 操作、主线程调度、参数校验、精确差值和重复请求编号。
- 前端执行类型检查和生产构建。
- 在现有测试框架允许的范围内，增加金额格式、在线时禁用修改和过期目标确认测试。

### 浏览器检查

使用 Playwright 对接接近生产的数据进行检查：

- 桌面和移动端布局。
- 空数据、加载、降级、错误和正常数据状态。
- 页中页、弹窗、表格、下拉列表、提示、图表和物品悬浮卡片。
- 页面、弹层和子窗口不存在裁切、被其他层遮挡或主题颜色错误。
- 现有账号、角色、邮件、公会、奖励、PVF、登录器和服务器监控流程保持正常。

## 部署与回滚

按兼容顺序部署：

1. 备份当前 Frida 脚本和配置。
2. 部署向后兼容的桥接操作，并验证本机回环接口。
3. 部署 Java 后端和新增审计表。
4. 部署前端静态文件。
5. 执行接口冒烟测试和 Playwright 主题、遮挡回归检查。

回滚时恢复上一版前端、后端 JAR、Frida 脚本和配置。审计表属于只增不改的新表，旧版代码不会使用，可以保留。

## 本期明确不做

- 修改背包或装备。
- 修改技能等级。
- 任意修改任务状态。
- 任意 SQL、GM 命令、封包、DP2 Hook 或热重载控制。
- 批量修改货币。
- 直接修改运行中角色的契约内存。
- 转让公会会长。
